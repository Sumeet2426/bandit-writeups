# Bandit Level 29 → 30

## Objective

Retrieve the password for Bandit Level 30 by exploring branches within a Git repository.

---

## Challenge Description

The cloned repository does not contain the password in the default branch. The objective is to investigate the repository's branches and inspect their contents to locate the password.

---

## Enumeration

After examining the default branch, I found no useful information. Since Git repositories can contain multiple branches with different versions of the project, I listed all local and remote branches. A development branch contained the information required to obtain the next password.

---

## Commands Used

List all branches:

```bash
git branch -a
```

Switch to the development branch:

```bash
git checkout dev
```

View the README file:

```bash
cat README.md
```

---

## Explanation

- Listed all available branches in the repository.
- Identified an additional branch named `dev`.
- Switched from the default branch to the `dev` branch.
- Inspected the project files in that branch.
- Retrieved the password from the `README.md` file.

---

| Command | Purpose |

---

## Key Learning

- A Git repository can contain multiple independent branches.
- Each branch may have different files, commits, or project states.
- Security assessments should include all branches, not only the default branch.

---

## Real-World Application

Development teams commonly use branches such as `dev`, `testing`, `staging`, and feature branches. Secrets, debug credentials, unfinished code, or vulnerable configurations may exist on these branches even if they are absent from the production branch. During source code reviews and penetration tests, examining every accessible branch helps uncover hidden information and security risks.
