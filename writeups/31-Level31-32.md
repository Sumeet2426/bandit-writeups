# Bandit Level 31 → 32

## Objective

Retrieve the password for Bandit Level 32 by modifying a Git repository, committing the required changes, and pushing them to the remote repository.

---

## Challenge Description

The repository contains instructions indicating that a file named `key.txt` must be committed and pushed. However, the repository's `.gitignore` file prevents `.txt` files from being tracked. The objective is to override the ignore rule, commit the file, and push the changes to receive the next password.

---

## Enumeration

After cloning the repository, I examined the project files and found a `.gitignore` file containing the rule `*.txt`. This explained why the required `key.txt` file was not appearing in `git status`. Since Git allows ignored files to be force-added, I used the appropriate option to include the file in the commit.

---

## Commands Used

View the repository contents:

```bash
ls -la
```

Inspect the ignore rules:

```bash
cat .gitignore
```

Create the required file:

```bash
echo "May I come in?" > key.txt
```

Force Git to track the ignored file:

```bash
git add -f key.txt
```

Commit the change:

```bash
git commit -m "Add key.txt"
```

Push to the remote repository:

```bash
GIT_SSH_COMMAND="ssh -p 2220" git push
```

---

## Explanation

- Examined the repository and identified the `.gitignore` configuration.
- Created the required `key.txt` file.
- Used `git add -f` to override the ignore rule.
- Committed the new file.
- Pushed the commit to the remote repository.
- The remote server validated the submission and returned the password for the next level.

## Commands Learned

| Command | Purpose |
|---------|----------|
| `git status` | Show the current repository status |
| `git add -f` | Force Git to add an ignored file |
| `git commit` | Save staged changes as a new commit |
| `git push` | Upload local commits to a remote repository |
| `.gitignore` | Define files that Git should ignore |

---

## Key Learning

- `.gitignore` controls which files Git ignores by default.
- Ignored files can still be tracked intentionally using `git add -f`.
- Understanding Git's tracking behavior is essential when managing source code and project artifacts.

---

## Real-World Application

Developers commonly use `.gitignore` to exclude temporary files, build artifacts, logs, and secrets from version control. During security reviews, analysts should inspect `.gitignore` to understand which files are intentionally excluded. Misconfigured ignore rules can result in sensitive files being committed or important files being omitted from version control.
