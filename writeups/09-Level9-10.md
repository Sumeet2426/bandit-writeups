# Bandit Level 9 → 10

## Objective

Retrieve the password for Bandit Level 10 by extracting a human-readable string from a binary file.

---

## Challenge Description

The password for the next level is stored in the file `data.txt` and is one of the few human-readable strings. The password is preceded by several `=` characters.

---

## Enumeration

After inspecting the challenge description, it was clear that `data.txt` contained mostly binary data. Instead of opening the file directly, I extracted all printable strings and searched for the pattern preceding the password.

---

## Commands Used

```bash
strings data.txt | grep "==="
```

---

## Explanation

- Used the `strings` command to extract printable text from the binary file.
- Piped the output to `grep`.
- Searched for lines containing `===`, as indicated in the challenge.
- Retrieved the password from the matching line.

---

## Commands Learned

| Command | Purpose |
|---------|----------|
| `strings` | Extract printable strings from binary files |
| `grep` | Search text for a specified pattern |
| `|` (Pipe) | Pass the output of one command to another |

---

## Key Learning

- Binary files often contain embedded readable text.
- The `strings` command is useful for extracting human-readable information from executable files, memory dumps, or unknown binaries.
- Combining `strings` with `grep` allows rapid identification of relevant information.

---

## Real-World Application

The `strings` utility is widely used during malware analysis, reverse engineering, and digital forensics. Analysts use it to extract URLs, IP addresses, file paths, commands, registry keys, and other indicators of compromise from executable files without fully disassembling them.
