# Bandit Level 25 → 26

## Objective

Retrieve the password for Bandit Level 26 by bypassing a restricted login environment and escaping into a shell.

---

## Challenge Description

Logging in as `bandit26` immediately terminates the session due to a restricted shell configuration. The objective is to understand the login environment, identify an accessible program, and leverage it to obtain a shell and retrieve the password.

---

## Enumeration

After examining the user's login shell in `/etc/passwd`, I discovered that `bandit26` used a custom shell instead of a standard one. Reading the shell script revealed that it launched the `more` pager. Since `more` provides interactive features, I reduced the terminal height so the pager would pause and allow interaction.

---

## Commands Used

Inspect the user's login shell:

```bash
grep bandit26 /etc/passwd
```

Read the custom shell:

```bash
cat /usr/bin/showtext
```

Reduce the terminal height:

```bash
stty rows 6
```

Log in:

```bash
ssh -i bandit26.sshkey bandit26@localhost -p 2220
```

Inside `more`:

```text
Press v
```

Inside Vim:

```vim
:set shell=/bin/bash
:shell
```

Retrieve the password:

```bash
cat /etc/bandit_pass/bandit26
```

---

## Explanation

- Identified that the login shell executed the `more` pager.
- Reduced the terminal height so `more` paused instead of exiting immediately.
- Used the `v` shortcut to open the current file in Vim.
- Changed Vim's shell to `/bin/bash`.
- Started an interactive shell from within Vim.
- Retrieved the password from the protected password file.

| Command | Purpose |
|---------|----------|
| `stty rows` | Change the terminal height |
| `grep` | Search for matching text |
| `cat` | Display file contents |
| `:set shell=/bin/bash` | Configure Vim to use Bash as its shell |
| `:shell` | Launch an interactive shell from Vim |

---

## Key Learning

- Restricted environments should be analyzed rather than assumed to be secure.
- Interactive programs such as pagers and text editors may expose functionality beyond their primary purpose.
- Understanding how applications behave under different conditions can reveal legitimate escape paths.

---

## Real-World Application

Historically, misconfigured interactive programs such as `vim`, `less`, `more`, and `man` have allowed users to escape restricted environments. During penetration tests and security audits, analysts review accessible programs to determine whether they expose shell escape functionality. System administrators can reduce this risk by disabling unnecessary interactive features or using properly configured restricted environments.
