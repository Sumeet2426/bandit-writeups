# Bandit Level 20 → 21

## Objective

Retrieve the password for Bandit Level 21 by creating a local TCP server and allowing a privileged program to connect to it.

---

## Challenge Description

A program named `suconnect` is available in the home directory. It connects to a TCP port on `localhost` and sends the current level's password. If the password is correct, the service returns the password for the next level. The objective is to create a listening server that receives the connection.

---

## Enumeration

Unlike previous challenges where I connected to an existing service, this level required me to create my own listening service. I first selected an unused port, started a listener using `netcat`, and then instructed `suconnect` to connect to that port.

---

## Commands Used

Start a listener:

```bash
nc -lvp 1234
```

Open another terminal (or background the listener) and run:

```bash
./suconnect 1234
```

After the connection is established, send the current level's password.

Alternatively:

```bash
echo "<bandit20_password>" | nc -lvp 1234
```

---

## Explanation

- Started a TCP listener on port `1234` using `netcat`.
- Executed the `suconnect` program and specified the listening port.
- `suconnect` connected to the local listener and waited for the password.
- Sent the current password through the established connection.
- After successful verification, the service returned the password for Bandit Level 21.

---

## Commands Learned

| Command | Purpose |
|---------|----------|
| `nc -l` | Start Netcat in listening mode |
| `-v` | Enable verbose output |
| `-p` | Specify the listening port |
| `./suconnect` | Connect to a local TCP service |

---

## Key Learning

- Netcat can function as both a client and a server.
- Understanding the difference between connecting to a service and hosting one is fundamental in networking.
- TCP communication is bidirectional, allowing both systems to exchange information.

---

## Real-World Application

Security professionals use Netcat to simulate network services, receive reverse shells, test firewall rules, debug applications, and troubleshoot network communication. Understanding how to create temporary listeners is valuable during penetration testing, incident response, and system administration.
