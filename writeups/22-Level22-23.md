# Bandit Level 22 → 23

## Objective

Retrieve the password for Bandit Level 23 by analyzing a scheduled Cron job and determining how it generates the filename containing the password.

---

## Challenge Description

A Cron job periodically executes a script that stores the password for the next level in a file located in `/tmp`. Unlike the previous level, the filename is not obvious and must be determined by understanding how the script generates it.

---

## Enumeration

I began by examining the Cron configuration to identify the script being executed. After reading the script, I discovered that it generated the output filename by computing the MD5 hash of the username. I reproduced the same calculation to determine the correct filename and then retrieved the password.

---

## Commands Used

```bash
cat /etc/cron.d/cronjob_bandit23

cat /usr/bin/cronjob_bandit23.sh

echo "I am user bandit23" | md5sum

cat /tmp/<md5_hash>
```

> **Note:** Replace `<md5_hash>` with the hash generated by the `md5sum` command.

---

## Explanation

- Examined the Cron configuration to locate the scheduled script.
- Read the script to understand its logic.
- Identified that the filename was derived from the MD5 hash of the string:
  
  ```text
  I am user bandit23
  ```

- Reproduced the hash locally using `md5sum`.
- Used the resulting hash as the filename in `/tmp`.
- Retrieved the password from the generated file.

## Key Learning

- Reading source code is often the fastest way to understand program behavior.
- Predictable filename generation can reveal the location of hidden files.
- Hash functions are commonly used to generate identifiers and filenames.

---

## Real-World Application

Developers often use hashes to generate cache filenames, temporary files, unique identifiers, and integrity checks. During penetration testing and incident response, understanding how applications derive filenames or object identifiers can help locate sensitive data, reconstruct application behavior, or identify insecure implementations.
