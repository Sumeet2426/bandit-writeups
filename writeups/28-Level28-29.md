# Bandit Level 28 → 29

## Objective

Retrieve the password for Bandit Level 29 by investigating the commit history of a Git repository.

---

## Challenge Description

The cloned Git repository contains a `README.md` file where the password has been replaced with a placeholder. The objective is to investigate the repository's history to recover the original password.

---

## Enumeration

After examining the current version of the repository, I noticed that the password was no longer present. Since Git tracks every committed change, I inspected the commit history and reviewed previous commits to identify the version before the password was removed.

---

## Commands Used

View the commit history:

```bash
git log
```

Inspect the previous commit:

```bash
git show <commit_hash>
```

Alternatively:

```bash
git show HEAD~1
```

---

## Explanation

- Examined the current contents of the repository.
- Identified that the password had been replaced with a placeholder.
- Viewed the repository's commit history using `git log`.
- Inspected the previous commit with `git show`.
- Retrieved the password from the earlier version of the `README.md` file.

---

## Commands Learned

| Command | Purpose |
|---------|----------|
| `git log` | Display the commit history |
| `git show` | Display the contents of a commit |
| `HEAD~1` | Refer to the commit immediately before the current one |

---

## Key Learning

- Git preserves the complete history of committed changes.
- Deleted or modified data can often be recovered from previous commits.
- Reviewing commit history is an important part of repository analysis.

---

## Real-World Application

Security professionals regularly inspect Git history during source code reviews and security assessments. Sensitive information such as API keys, passwords, private keys, and tokens may have been committed in the past even if they have since been removed from the latest version. Examining commit history helps identify secrets that remain exposed within the repository.
