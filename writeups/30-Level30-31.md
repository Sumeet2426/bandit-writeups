# Bandit Level 30 → 31

## Objective

Retrieve the password for Bandit Level 31 by investigating Git tags within a repository.

---

## Challenge Description

The repository does not reveal the password through its files or branches. The objective is to inspect Git tags, which may reference historical snapshots containing the required information.

---

## Enumeration

After reviewing the repository contents and branches, I explored the available Git tags. A tag named `secret` was present. Inspecting the tagged object revealed the password for the next level.

---

## Commands Used

List available tags:

```bash
git tag
```

Inspect the tagged object:

```bash
git show secret
```

---

## Explanation

- Listed all tags in the repository.
- Identified a tag named `secret`.
- Used `git show` to inspect the tagged commit.
- Retrieved the password stored within the tagged object.

---

## Commands Learned

| Command | Purpose |
|---------|----------|
| `git tag` | List all tags in the repository |
| `git show <tag>` | Display the commit or object referenced by a tag |

---

## Key Learning

- Git tags provide references to specific commits.
- Tags preserve historical snapshots and are commonly used for releases.
- Repository analysis should include tags because they may expose information unavailable in the active branches.

---

## Real-World Application

Organizations frequently tag production releases such as `v1.0`, `v2.1`, or `release-2025`. Older tagged versions may contain secrets, vulnerable code, or configuration files that have since been removed from the latest branch. During source code audits, reviewing tags can uncover security issues that would otherwise remain hidden.
